# 下载 / 归档批量更新

多选工具栏新增“批量更新”，两页可分别设置开关、顺序，底部预览同步显示。
新默认配置放在暂停之后；旧自定义配置追加该按钮并开启，保留已有按钮的开关与顺序。

## 操作

1. 选择漫画，点击批量更新，确认检查。仅处理普通下载 `downloaded` 和归档 `completed`。
2. 服务逐项读取最新详情，沿新版链接查到最终版本（循环或超过 20 个版本视为异常）。
3. 查看结果，勾选要更新的项。归档同时展示官方／机器人来源、原图／重采样、大小及费用。
4. 点击“确认更新”（不带数量）；报价失败项不可提交。
5. 任务确实注册后才显示“任务已创建”，不是“下载完成”。已创建但归档停止／暂停单列计数和原因。

页面关闭不销毁服务：对应下载／归档页更多菜单中“查看批量更新任务”可重开同一批次，包括完成／取消后的结果，不重新检查或购买。列表只显示发现新版的候选（含报价／提交失败），其余结果仅在统计计数。
顶部只保留简短归档提示，列表与按钮之间显示各状态、选中项大小／数量／GP／Bot GP。官方 GP 仅读取明确数字，不把 Credits 或 Bot GP 混入；未知大小或 GP 显示“—”，每项原始报价保留。
提交时可隐藏窗口，后台继续。
Android 同一后台通知现在包含批量更新检查／提交的漫画数进度，刷新约每秒一次；待确认时不显示进度条，单独存在时无暂停／继续按钮，点击只重开当前清单，不触发提交或费用。完成／取消结果短暂显示后自动收起；归档“任务已创建”不等于下载完成。
通知暂停会阻塞检查和后续提交的检查点，恢复仅解除该门控，不自动确认报价。执行中的网络请求可能先结束；已创建任务仍由原有下载服务管理。
统计改为主题自适应卡片，根据实际翻译文本宽度排每行 2～3 项，状态计数采用更紧凑的同列布局。
再次点击任一页的批量更新会显示当前批次，不产生并行批次。
“停止后续项目”仅取消尚未提交项；已创建下载与发生的费用不撤回，不删除新版或旧版。

## 安全与兼容

- 普通下载复用现有旧版本图片复制流程，并继承当前分组、原图选项，不删除旧版本。
- 归档重新下载完整新版，继承原分组、原图、解析来源；不复制旧下载链接、大小或路径。
- 所有读取串行，启动间隔约 2 秒；仅网络错误额外重试一次。详情绕过缓存。
- 检查、提交前均验证完成状态；本地已有目标、新版重复、失效版本链均跳过或报告错误。
- 任务注册入口与普通手动下载共用 GID 创建锁，避免并发覆盖同一任务。
- 报价仅读取，不购买；官方费用逐项展示原始字符串，不伪造多币种总价。
- 机器人报价沿用现有估算公式，检查阶段缓存余额一次，确认时再次验证选中项总费用。
- 启动归档前刷新报价，价格或大小变化会停止该项，要求重新检查并确认，不按旧报价扣费。
- 批量新增归档完整 pipeline 默认串行上限 1。取消批次后仍跟踪已启动 pipeline，后续批次不会绕过槽位。
- 手动暂停不会被批次自动恢复；通知栏全局暂停时停止检查／提交后续项。
- 详情页原有单项更新接口行为保留；批次通过结构化注册结果判断，不使用吞错的 `Future<void>` 作为成功依据。

不新增数据库版本、原生通知类型、归档增量迁移或旧版自动删除。
已创建的任务由原有下载页、Android 通知与恢复机制接管。
检查／待提交清单只保存在当前进程，应用被杀死后不承诺恢复这份批次清单。
报价是确认时的估计，站点最终收费以实际请求为准；测试不会触发任何真实费用。
